# 视觉探索与情绪板

交付帮助用户作出视觉决策的实际作品，主载体是本地可运行 HTML，附同版 PNG 总览；首版还须具备经实测的 PDF 导出能力，单个项目按需生成。每个**完整方向**都必须有服务该方向问题的真实 Shaders 研究，草稿不计完整方向。不要以 Shader Demo、漂亮背景、通用卡片墙或提示词包宣布成品完成。

## 启动与职责

先读原始 brief、最新纠正、锁定及真实素材，判断本轮是研究/提示词、完整制作还是局部修订。研究或提示词请求只交付相应结果，不运行媒体制作，也不称其为完整情绪板。复用已有项目入口与有效授权；项目文件写在用户工程内，客户 brief、身份、媒体和生产回执不得进入 Skill 源包。

正式制作须显式加载本文件及相关支持资源，使用当前宿主真实工具；发现描述、生成启动提示、`agents/openai.yaml` 或 `skill_loaded: true` 都不证明实际使用。先读 [宿主与执行](references/host-adapters.md)，核对本机命令帮助、实际能力和运行记录，不能把待派发准备态说成代理已执行。

指定一位主责视觉创意总监兼美术指导，具备当前媒介判断能力，承担整体取舍。在 brief、锁定及已授权预算内，由其决定开放的艺术变量、删减、合并与重做，不逐项要求用户投票；涉及目标、锁定、外部权限或预算变化时才交回用户。主责推荐不登记为真人偏好或批准。

技术执行为创意技术/技术美术，负责实现与媒介适配，可以用实际样本提出更好的方案。专业异议给具体画面、时刻或操作及反例，由主责整合，不按人数表决。重要成品由未参与制作者独立审阅；艺术取舍权不能免除已确认的质量失败。三种责任不要求每次小修改新增三位代理，主责可以兼技术执行，不能兼自己的独立首评。简短角色委托见 [prompts/creative-director.md](prompts/creative-director.md)，UI 元数据不是实际代理配置。

所有 Codex 语言代理使用 `gpt-6.1-sol` / `ultra`；支持参数的入口显式传入，并核对实际 `turn_context` 或等价运行证据。入口无法指定或核实则记录限制，不擅自降档。提示文字、默认配置、实际运行分别保存。

## 创作与判断

完整制作先读 [创意合同](references/creative-contract.md) 和 [品质合同](references/quality-contract.md)，有现有素材时读 [素材操作边界](references/asset-operations.md)。

1. 在方向制作前，分别建立**研究对象**和**HTML 承载体验**的成功条件、关键失败与实看标杆。主次只决定本次决策与修订优先级，两类品质不能平均互偿。网页精彩不能证明产品材质/影像方向成立，研究强也不能抵消普通或妨碍比较的网页。
2. 连接决策问题、参考拆解、可观察的视觉假设、代表画面与 Shader 研究、实际对照及修订/淘汰，再展开完整板面。主责提出值得坚持的观看主张，以代表作品和最有力的反例判断，允许推翻原主张。不规定固定方向/图数；名称、颜色、速度或不同 Shader 不自动构成不同方向。代表研究成立不等于正式展开已通过。
3. 先选择足以回答问题的样本与媒介，再决定 Shaders 的作用，注明支持对象、承载体验或两者。图形、摄影、CG 或空间试验按问题选用，不从现有三种配方反推全部创意。实际能力边界见 [Shader 运行](references/shader-runtime.md)；缺少核心表达能力时说明具体缺口与可行路径，不以改参数或漂亮背景掩盖。每完整方向仍须有相关的真实 Shaders 研究，但无需由 Shader 独自模拟所有对象关系。真实主体锁定时可用合法代理资产探索，不能宣称真实产品已验证；缺授权或素材的核心假设保留待验证。
4. 明确交接：**采用什么关系、不采用什么内容、什么仍未证明**，绑定实际样本、版本和使用范围。推荐、网页点击、用户明确批准、下游正式批准分开。

## 制作与恢复

技术执行读 [Shader 运行](references/shader-runtime.md) 和 [项目合同](references/project-contract.md)。通过包内 `scripts/moodboard.mjs --help` 及相应子命令帮助使用已实现入口；能力、精确参数与不支持项以当前运行结果为准。缺依赖、宿主、浏览器/GPU、资源或版本时报告实际失败，不生成假回执。

使用锁定依赖、本地 bundle、自编合法配方和回环服务；运行时不靠云预设、远程 MCP、`latest` CDN 或未验证 iframe。主板优先展示作品与方向，技术/来源按需展开；非活动 Shader 暂停或销毁。中文、移动视口、键盘/触控、减少动态及失败回退均需实际检查。

临时调参和时间与已提交快照分开；保存、导出或提交审阅前校验并提交当前有效状态。poster、HTML、导出、检查与审阅绑定同一快照/配方/构建。只让受影响证据失效，其他方向可按准确版本复用；不得用默认参数或旧 poster 冒充当前画面。

素材操作按授权类型、影响区域和不可变属性判断，源文件保留不证明最终呈现未变。位图创作/编辑使用适用图像工具；原样贴图、HTML 独立层及已授权程序研究按其真实实现执行，操作授权与工具路由分别满足。开发/本地制作不自动授权付费、上传、账户操作或业务发布；已有明确授权继续有效，不为普通本地修复新增确认。

## 检查、修订与完成

实际作品 → 技术/视觉自检 → 独立首评 → 最高影响问题修正 → 受影响回归 → 修订复核。给独立审阅者原始要求、最新纠正、锁定、两类成功条件、制作前标杆及实际产物版本，执行解释/自评另存；先收回“先首评后对照”确认，封存首评后才提供解释。不得把参与制作者的检查称为独立首评。

实际启动并完整浏览 HTML，操作相关交互，观看每种动态的有效过程与循环接缝，查看最终 PNG/PDF；静帧不代动态，文件生成和测试绿灯不代画面品质。按当前标杆分别给对象与承载体验结论，修复授权范围内问题并复查。按任务预算停止，预算到达不自动通过，不用多轮评分或代理人数证明进步。

首个正式版本以新代理执行完整真实任务，并以跨媒介第二情境前向使用，验证输入、判断、制作、反馈、局部修订与下游交接；合法自有/虚构示例可以使用，不能伪装客户批准或市场结果。

交付须同时具备实际 Skill 使用、每完整方向的 Shaders 有效绘制与相关可见作用、同版 HTML/所需静态输出、技术及观看证据、两类品质与独立审阅、三类交接及重开方法。缺项准确保留 `partial`、`unverified`、`needs_revision`、`unsupported` 或 `independent_review_pending`。技术状态、对象品质、承载品质、独立审阅、交付就绪、用户接受分别报告；`ready_to_deliver` 不等于用户验收或真实获奖。
