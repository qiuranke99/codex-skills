# 审阅、拒绝条件和恢复

## 三类结论分别成立

1. **身份与事实：** 实际产品结构、字标、必要文字、SKU对应和用户锁定项是否正确。
2. **创意与美术：** 创意是否表达目标；品牌关联、构图、信息层级、摄影材料和细节是否达到任务要求。
3. **技术与交付：** 实际规格、文件可用性、完整性、可编辑性及媒体播放是否符合交付。

不采用可以互相抵消的总分。关键产品、Logo、必需文案、SKU或用户硬约束错误，直接判相关成品需要修正；其他项满分也不能批准。创意与美术同样不能因“技术通过”而自动通过。

## 按实际媒体检查

| 媒体 | 必要检查 |
| --- | --- |
| 图片 | 实际打开最终文件；看整体、实际使用尺寸，以及身份、文字、材料和合成关键细节 |
| 版式与文档 | 渲染并逐页/逐版检查最终导出；检查溢出、缺字、图层或字体替代 |
| 三维 | 查看相关角度的预览渲染，核对结构、材质与镜头；不能只看建模脚本成功 |
| 动画/视频 | 播放受影响片段，检查运动、连续性、剪辑、文字与音画；最终成片完整回看 |
| 印刷/生产 | 依据真实输出条件预检并核对打样；屏幕效果不能单独证明印刷或制造可用 |

用户只授权低成本预览时，明确它的检查范围。正式最终文件仍需最终检查。没有观看证据就不能把“程序成功”“文件存在”“帧数符合”写成视觉通过。

## 审阅记录

每项成品保留简明记录：原始要求来源、实际成品版本、相关输入版本、检查方法、观察事实、判定、证据位置、待修正项和应保护部分。

使用 pass / fail / unverified 表示检查结果；unknown不能写成pass。仅将与当前成品确实无关的项目排除，并在交付约定中说明，不能事后删除失败检查项来制造通过。

审美判断应有具体观察：例如“缩到实际投放尺寸后卖点不可读”“产品边缘反光与场景光方向冲突”“图形抢走产品的第一视觉层级”。“高级感不够”需要继续定位，不是可执行修正说明。

## 自检与独立审阅

默认按任务需要自检，不自动扩增代理或任务。用户要求独立验收或既有流程指定验收者时：

- 先声明真实身份、是否参与制作、是否已接触执行者解释或完成结论。
- 先阅读原始需求、全部纠正、必要运行信息与实际产物，保存并封存首评，再看执行者说明。
- 首评与最终对照绑定实际版本；改变判断要给出原因和复核证据。
- 已接触说明或参与制作的人可以补充检查，但不能冒称未受影响的独立首评。用户/环境禁止代理时严格遵守；没有合适验收者则明确待独立验收。
- 遵循目标环境适用的封存和核对协议。本包交付检查器只检查本地文件与记录，不能代替该协议，也不能证明阅读顺序、真实身份或认知独立。

## 修正还是重新制作

**局部修正：** 方向仍获认可，问题局部且修正机制有把握时，明确修正区和保持区，保留原有有效构图、光影和交互。

**更换制作路径：** 问题来自工具能力、文字重绘、复杂遮挡或产品身份不稳定时，换用真实资产、排版、贴图、合成或其他已授权方法。

**重开方向：** 用户否定核心概念或多个基础体系无法相容时，记录废弃方向并从最后有效决策接续。不要把已否决图混入新方向；只保留明确认可的判断。

“重做”不能默默改变用户锁定的产品身份、创意、构图、时长或其他约束。需要突破约束才可解决时，先制作可审阅的证据与选择，再请求具体决定。

## 系列覆盖与恢复

从原始任务建立所需成品清单，不以现有输出数量反推已经完成。每项明确对应 SKU/场景/比例，禁止遗漏、重复占位或用同一文件冒充不同内容。

相关输入、品牌核心或产品资料更新时，重新核对依赖这些内容的成品。输入摘要按每项成品的实际相关资料计算，减少无关变更引起的误报；完整交付仍绑定当前任务约定。

保留已完成成果、真实阻塞和下一项可执行动作。不得擅自创建重试自动化、绕过账号限制或以协议工作替代制作。
