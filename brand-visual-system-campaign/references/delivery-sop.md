# 品牌视觉系统与系列素材扩展：成品交付 SOP

版本：1.0.0。目标是完成用户要求的实际成品和可继续维护的交接资料。本文件是可单独阅读的人用 SOP；自动执行入口为本包 SKILL.md。

## A. 明确本次交付

读取原始要求、最新纠正、批准内容和实际素材，形成最小交付清单。每项包含用途、SKU或对象、数量/版本、比例与实际尺寸、格式和关键检查项。

默认继承既有品牌。只有任务明确包含品牌建立或重塑时，才进入相应视觉开发。局部修改保留镜序、构图、时长、产品身份和其他已锁定内容。

目标不明确但可以采用常规制作选择时，提出合理默认并继续。缺少原始字标、准确标签或未知结构时，先推进不受影响的部分；需要这些资料的成品不得凭空补造。

## B. 确定创意与视觉规则

使用 creative-system.md 的方法连接传播主张、表现机制和品牌关联。把已批准事实、长期品牌规则、活动规则和可变项分开。

原有审批与授权持续有效。只把会改变目标、事实、主要方向、预算或用户保留审阅节点的决定交回用户；不要把内部检查表变成逐步索要确认的流程。

## C. 选择能完成最终文件的制作路径

先检查环境实际提供的工具、输入通道、导出能力和使用授权，再选择方法。Skill 的文字规则不会自动提供图像工具、字体文件、供应商账户、精确深度控制或三维模型。

| 需求 | 制作安排 |
| --- | --- |
| 场景、摄影氛围、创意形象 | 使用可用的图像生成/编辑工具；保留输入与关键设置，实际检查生成效果 |
| 精确平面字标与文案 | 使用原始矢量/真实字体和排版工具完成，核对字形、内容、层级和对齐 |
| 精确产品 | 优先保留真实产品或批准资产；需要重建时核对结构证据，不能把近似生成当成准确产品 |
| 曲面包装和动态标签 | 采用能正确处理曲面、透视、遮挡、反射、景深和运动的贴图或合成方法 |
| 品牌规范和可编辑版式 | 在实际文档/布局工具中制作可编辑内容；导出后逐页或逐版检查 |
| 动态应用 | 完成所需生成、剪辑、声音和导出；保持产品/品牌事实，实际播放检查 |
| 印刷或生产文件 | 在已知尺寸、版型、材料和输出规范下制版、预检、打样；只有概念渲染时标明实际能力缺口 |

精确元素与生成画面的交界也属于制作责任。贴字后要检查边缘、变形、反光、光照、纹理、遮挡和景深；不能只证明文字内容正确。

用多个工具完成任务时，交接实际文件、有效版本和输入职责，不让用户承担内部转述。不得假称已调用不可用的工具，也不默认安装、订阅、登录或上传到未经授权的外部服务。

## D. 完成代表性成品，验证风险

以低成本但能揭示主要问题的预览开始。测试范围由实际需求决定，常见风险包括：

- 强风格外部参考导致品牌或产品身份漂移。
- 曲面、透明体、反射或遮挡影响产品与文字准确性。
- SKU差异被错误套用，或系列间失去共同逻辑。
- 横竖比变化、长文案和本地化导致层级崩溃。
- 真实使用尺寸下不可读，或动态中出现形变/闪烁。

先解决会导致整批返工的问题，再扩展相同制作路径。只通过一种条件的测试，不自动声称其他使用范围已验证；尚需验证的范围继续完成测试。

## E. 检查、修正与复查

按 review-and-recovery.md 区分关键错误、创意美术问题和技术问题。每次修正列出“改哪里”和“必须保持什么”，选用合适的局部编辑或重建范围。

授权范围内继续修正到达到要求。若同一方法反复失败，改变导致失败的制作机制；无法解决时尝试有依据的替代路径，不能只增加形容词或无限重复生成。

修改有效输入或规则时定位受影响的结果。每次导出或修正后，以最终文件重新检查，不让旧版检查替代新版检查。

## F. 完成系列及其实际格式

根据用途组织成品，核对用户要求的每个 SKU、场景、比例和版本。差异应来自批准变量和具体传播情境。对所有最终输出做适当检查，不能用一个通过的样张代表全部成品。

默认数字静态素材可交付最终 PNG/JPEG、可用的预览索引和实际制作源文件（存在且适用时）。具体任务要求 SVG、PDF、PSD、PPTX、视频、印刷文件等时，按所需格式真正制作并验证。文件后缀、像素尺寸和“4K”文字都不能单独证明质量。

可编辑交付包含实际可编辑对象及其必要依赖，明确哪些元素已经栅格化。不能将单张图片嵌入文档后宣称所有元素可编辑。

## G. 交付完整性检查

在实际项目目录保存：

- 原始需求与批准/纠正来源。
- 当前有效输入及其角色、版本，必要的素材使用信息。
- 最终成品与所需制作源文件。
- 对应最终版本的检查、修正及剩余事项记录。

使用 delivery-records.md 的 contract.json 和 delivery.json 核对交付范围、实际文件哈希、相关输入版本和检查记录。运行本包交付检查器；失败项修复后重跑。此检查器不替代看图、播放、审美判断和客户验收。

## H. 用户实际收到成果

最终回复提供可直接访问的成品和必要源文件，说明交付范围及实际检查。没有剩余问题时直接交付，不以“是否继续”为结尾。

完成交付和用户最终批准分开记录。用户保留的审阅节点仍待用户判断；不得自己制造用户批准。若真实能力或关键输入不足，明确哪些成品未完成、已经交付什么，以及最小恢复条件，不用规划文档假装任务完成。
