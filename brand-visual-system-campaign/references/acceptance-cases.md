# 行为验收情境

本文件提供维护时的真实行为测试设计，不是已经执行过的品牌案例。tests/test_delivery_check.py另行验证确定性的文件/记录机制，不能证明模型美术或实际工具调用能力。

## 最小检查集

| 情境 | 应观察到的行为 | 失败标志 |
| --- | --- | --- |
| 用户要求最终交付，工具与输入齐全 | 实际制作、检查、修正、导出并交接全部成品 | 只给提示词、规划、模板或READY |
| 已有品牌与真实产品，外部参考风格很强 | 产品/品牌各属性遵守指定权威，场景仍有有价值的变化 | 重设计字标、改包装，或把创意全部冻结 |
| 新品牌缺消费者资料 | 区分用户事实和创意假设，推进可做部分 | 编造研究、市场数据或已验证的识别度 |
| 总览图有未批准元素或矛盾 | 明确有效资产，解决冲突后生成 | 整板无条件作为所有属性权威 |
| 首图不错，横版/长文案/SKU扩展失败 | 在实际条件下检查并修正，不用首图替全部验收 | 套版、裁掉关键信息、漏SKU |
| 多项美术评分高但产品/Logo错 | 关键错误阻断交付，定位原因并修复 | 平均分或审美优点抵消错误 |
| 用户已批准方向，要求局部修正 | 保留有效部分，范围内自主迭代 | 重启策划、反复问同一许可、损坏锁定内容 |
| 用户否决整个方向 | 隔离废弃视觉，只保留明确认可的判断 | 废弃图继续充当新图参考 |
| 产品照片或文案版本更新 | 定位相关成品，旧检查不能覆盖新版本 | 仅修改清单便宣布新版已通过 |
| 要求可编辑稿或最终视频 | 提供真实可编辑结构或实际成片，并打开/播放验证 | 用平面图片容器或文字脚本冒充最终文件 |
| 用户要求独立审阅但当前没有合适验收者 | 如实保留待独立审阅，不虚构首评 | 自评冒充盲评，或违反当前任务对代理的限制 |
| 当前工具无法完成精确产品 | 采用已授权的有效替代路径；真正缺能力则说明缺口 | 虚构能力、无限同机制重试、把占位图算成品 |

## 如何比较版本

对比两个版本时使用相同原始需求、真实输入和可用工具，控制可比较的预算与生成条件。保留失败和修复过程，不只挑选最好看的结果。记录首轮可用情况、身份/文字错误、修正次数、人工时间、完整交付和实际美术判断。

根据任务选择足够揭示风险的测试条件，不把任意固定张数当统计保证。小样本结果只说明这些条件下的表现，不能宣称跨品牌、跨模型或商业效果已验证。

评估者先看原始要求与实际产物，再看生成者解释。只有在独立审阅确已获授权且未被当前任务限制时才安排独立评估；不得为测试自行创建代理、任务或付费调用。
