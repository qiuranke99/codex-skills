# Skill维护的独立行为试验

只在创建、实质修订或发现能力退化时使用。常规提示词任务不用运行整套试验，也不要求用户批准一套测试流程。

## 执行协议

结构验证通过后，让独立代理读取实际Skill并完成真实请求。只给请求、Skill路径和最小原始素材，不给预期答案、怀疑的错误或修复建议。代理需要实际打开全部图片；纯文字题不能替代多模态试写。合成示意素材可用于机制测试，必须标注合成、无真实产品/光学效果证据；不能借此声称识别真实复杂标签已验证。

在仓库外的隔离临时目录保存原始测试图片、请求、生成的完整提示词、后续修改请求、改稿和独立审阅。不要把客户参考图、品牌、私有提示词或模型提交产物进入公开Skill包。验收报告记录读到的包版本/哈希、实际输出及不足，不用预设“PASS”模板代替观察。

## 覆盖场景

测试输入与审阅标准分别交给作者和审阅者；作者只拿真实请求，不拿本节的预期判断。

| 场景 | 原始请求的关键条件 | 审阅要观察的行为 |
| --- | --- | --- |
| 竖直关键帧 | 关键帧只锁一个中途构图；另一请求明确全程竖直 | 前者不误锁全程；后者用合法平移/纵深与相机大路径保留动态 |
| 大动态与文字阅读 | 清晰正面标签、强相机/料体动作，关键帧带冲突字样 | 标签权威正确，局部阅读窗不吞掉整镜，不能单独扶正文字 |
| 固定背景/灯具 | 分别指定背景照明固定、背景画面固定、全部灯具固定 | 不将三者混为一谈；由合法表面运动产生动态，背景不乱扫光 |
| 多SKU与状态 | A多视角/开盖状态、B不同包装，指定各自出镜数 | 不合并第三SKU，不把状态或多图当新实例；原图用途有对应表 |
| 用户顺序 | 指定先A形态→A过程→B质感→双产品落版，固定镜数 | 在指定顺序内创造节奏，每镜独立贡献，不能重排成默认配方 |
| 过程回售卖 | 演示不可逆混合/消耗后需要完整售卖状态 | 明确不同展示时刻；不倒吸复原；结尾先发展再稳定>=1秒 |
| 跨段修改 | 首稿有平台测试限制，后只改跨段动作完成时刻 | 修改实际传播到相关接口/局部时间/编号，保留无关锁定内容 |
| 画幅与输入限制 | 分别9:16、16:9、1:1，不同单次时长/图数/字符限制 | 不只改画幅标签；按本次入口限制重分单元与图，精确计数 |

至少产出能覆盖以上问题的独立完整试写和一次真实后续改稿。允许一个案例覆盖多个问题，不用凑固定案例数量。

## 反例审查

另一个代理从实际输出和下列失效片段中判断问题与最小修法：

- 全镜“缓慢环绕”，用一个局部拉焦声称景别变化；主体纵深移动替代相机大运动。
- 正面字清楚但整镜冻结，或大幅转瓶时标签脱离表面一直朝前。
- 透明胶片遮满画面成为黑幕；固定背景下全屏扫亮或全局曝光跳变。
- 多张A状态图增殖出多瓶；A瓶身与B盖拼成第三款；关键帧错字压过正面权威。
- 前镜完成释放后后镜又从释放开始；已混合料体自动分层回到售卖状态。
- 29—30秒仍在入场/变焦/淡出却声称稳定一秒。
- 改了前段末态但后段正文不动；两段各自30秒、重复跨段事件或只更新表不改正文。

反例可以有很漂亮的术语和形式完整的字段。要求审阅者指出具体状态/时序/观察矛盾，不能做关键词匹配。发现问题先判断来自Skill缺口、执行偏差还是素材不足；只对有证据的缺口补窄规则，修订后重测受影响行为。

可用 `scripts/test_check_delivery.py` 验证字符/时间工具，工具测试与试写语义审查分开报告。通过试写不等于生成效果已验证。
