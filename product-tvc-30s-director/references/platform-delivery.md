# 真实平台转写与交付

仅在平台核查、分段、字符限额或接口修改时读取；不在这里保存各模型的易过期限额。

## 核查使用入口

相同模型名在官网、第三方网页和API的功能可能不同。记录实际模型/版本、入口、核验日期、官方文档或实际界面证据，以及单次时长、参考类型及用途、图片数量、画幅/尺寸、文本限制与计数单位、是否支持声音。只把有证据的功能写成平台能力。

优先使用用户给定入口与已有当次证据，需更新时查该平台一手文档/真实界面。不把其他站点的经验、旧次任务或参考预演当成该入口支持证明。不为核查而提交生成、上传私有素材或启动付费任务。

模型未指定：先交付完整30秒通用稿及素材代号，说明实际上传标签尚待映射。模型已指定但入口限制未知：能核实的继续核实，无法核实的标明未知；必要时只问入口或关键限制。不得声称“已可直接提交到该平台”来掩盖未知项。

用户提供的测试限制可以作为本次输入合同，明确来源为“用户给定”，不伪造官方核验。某入口只能首/尾帧或不能绑定全部所需图片时，不默默将关键帧改成端点或丢弃身份图；解释不相容的具体用途，并在已授权范围内给通用稿/可行映射。

## 生成单元与成片时间

镜头属于创作结构，生成单元属于平台提交结构；一个单元可含多镜，一个镜头也可能跨单元。根据真实时长与参考机制决定分段，不因有两张关键帧就固定两段。

每个单元输出：

1. 覆盖的全片时间、保留镜号、独立局部时间；额外源素材余量另列并写明裁切保留范围。
2. 本段上传编号—原文件/素材代号—用途—适用镜头。编号在每段重新开始，正文与表对应；重复使用的源图也须在本段列明。
3. 可独立复制的完整正文：开头一次写本段SKU与正确状态、各参考权限、整体背景/影调/材质；随后逐镜写可见事件、运动与切点，不能依赖上段隐藏上下文。
4. 跨段接口：产品数量和状态/液位、动作阶段、机位/观察目标/景别、屏幕动势、光影、声音（若有）。连续事件匹配必要进度；视觉联想或展示时刻切换说明关系，不强迫世界空间连续。

图片超过限制时先按属性与镜头职责选最小必要集合，只有证据冗余才可不上传；素材台账仍记录所有看过的输入与舍取原因。不能默默舍去唯一文字/结构权威。参考不足以满足硬锁时问具体缺口；不擅自做拼图、生图或伪造平台能理解图集。

画幅改变必须检查运动包络、景别变化、标签可读尺寸及最后构图，不能只替换“9:16”为“16:9”。用户指定像素尺寸优先，入口不支持时清楚标出约束，不能将目标输出尺寸声称为生成证据。

## 修订的接口闭环

先确定用户改的是事实、动作、时间、参考用途、平台限制还是局部文案。保留有效且锁定的正文；检查改动所在镜的入口/出口，以及跨段状态重新汇合前的依赖。把必要的相邻段改动实际写进完整正文；未受影响内容保留。时间改变后重算全片、局部时间、余量和最终停留；编号改变后复查所有图片指代。可简短说明修改的接口，不给整段未变内容换一套创意。

## 精确计数与机械工具

将每个实际提交正文单独存为UTF-8文件，包括该单元全局约束及逐镜文本；创意说明、上传表、核查注释放在文件外（若入口也提交这些内容则计入）。不要只数逐镜部分。遵从平台计数单位；未知单位时同时报告Unicode码点/UTF-16长度并留余量，不声称二者等于所有平台的“字数”。先去重复规则与修辞，不能为压字数删掉状态、动作、时序或接口。

`scripts/check_delivery.py` 相对包目录运行，纯标准库：

```text
python scripts/check_delivery.py --prompt unit-a.txt --prompt unit-b.txt --limit 5000 --reserve 250
python scripts/check_delivery.py --timeline timeline.json
```

数值只是命令示例，不是任何模型限制。可指定 `--count-unit utf16`。时间表格式：

```json
{"shots":[{"id":"S01","start":0,"end":8},{"id":"S02","start":8,"end":21},{"id":"S03","start":21,"end":30}],"hold_start":28.5}
```

这也不是默认三镜结构。工具只检查0—30秒连续覆盖、唯一镜号、正时长和申报的最终停留时间至少1秒；不能证明28.5秒时画面真的落定。审稿者必须从正文判断构图、姿态、品牌信息是否已稳定，所有转场/变焦是否已结束。脚本报告通过只代表算术/长度通过。
