# 从实际预演写完整提示词

用于编译、语义审读、附件规划和交付。正文模板在[assets/prompt-template.md](../assets/prompt-template.md)，运行格式和命令见[运行契约](runtime-contract.md)。本包默认交付提示词和素材，不自动提交最终视频。

## 1. 先核对实际版本

编译使用本次实际渲染的契约与证据。核对布局版本、源文件哈希、blend、逐镜文件、合成文件、帧率、镜头时间及最后稳定段；契约修改后旧渲染证据失效，不能只刷新一个哈希继续使用。布局修正、动画修正和文案修正分别影响哪些文件，按实际依赖重做。

三类内容写法不同：

- **预演已实现**：时间、镜号、位置/朝向/路径、焦段、主体动作、切点和构图变化。与实际媒体和读回证据一致。
- **外观设计**：产品真实材质、包装文字、影调、精细光影及未模拟的物性。以对应产品/风格事实和锁定设计为依据，不冒称白模证明它们。
- **未知或未实现**：不编成既成效果。可修正的先修正；实际能力或授权不足时保留缺口，完整交付状态据此限定。

机器编译确保引用和版本相容，不能独自判断文案是否与画面含义一致。编译后逐镜读实际输出，与视频的可见事件对照，修掉方向、顺序、时间和状态矛盾。

## 2. 沿用正文层级与写法

`compile`实际读取本包唯一的`assets/prompt-template.md`，按实测镜头展开同一个逐镜块，避免示例模板与真实编译输出分叉。保留以下组织顺序，并按产品内容填充：

1. 成片任务、时长、画幅、镜数与剪辑关系。
2. 输入及其职责。
3. 视觉风格参考锁定。
4. 产品身份与状态锁定。
5. 包装文字身份锁定。
6. 文字可见度原则。
7. 美术置景与布局结构锁定。
8. 摄影系统。
9. 动态光影系统。
10. 料体与材料过程。
11. 白模预演使用规则。
12. 按连续时间排序的逐镜正文与最终停留。

用户另给模板时以其层级和写法优先，但仍保留完整必要信息。旧稿的品牌、机械机构、配方、颜色、无缝场景、镜数、固定焦段和时长均不是新任务事实。模板字段仅在作者准备过程中存在，最终实际正文须填完并删除无关占位。

每镜先写镜号、全片时间和实际摄影配置，再以自然语言推进：起始视点/主信息 → 相机路径与朝向 → 产品/料体/置景独立动作 → 光影具体变化 → 阅读窗口 → 切出与接入关系。多动作按因果和时序表达；不要把完整正文削成参数表、分镜大纲或一串关键词。

“机械臂、微距探针、柔光、张力”均不能代替可见结果。把关键位置、占比、方向、幅度、速度与时刻转成可理解的摄影语言；无需把坐标、四元数和日志塞给视频模型。对相机和主体分别描述，不用一条“跟随运动”覆盖全部动作。

全局身份和参考权限开头写一次，逐镜只补本镜的状态与变化。精简去掉重复口号，保留状态、路径、时序、物性和切点。用户要求完整改稿时交付更新后的完整正文，修改影响到相邻段时实际补齐接口，不能只说“自然衔接”。

完整审读后只改文字、字符数或平台附件/单元映射，使用`finalize`对已冻结媒体定稿，输出新的正文文件、附件映射与哈希；具体格式见[运行契约的定稿入口](runtime-contract.md)。它不解析全文含义或修改原预演，代理必须在`semantic_review`写清与实际动作、状态和时间的对照。涉及真实镜头、几何、切点或时间改变时重新建立对应lane，不在定稿JSON中伪改媒体事实。

## 3. 参考职责与真实生成附件

“作者分析素材”与“视频模型附件”分表管理。默认中性素材ID与文件名，不预设平台上传语法。

编译器生成的`attachments.json`是带哈希的中性素材库存，可能包含全部作者分析资产；它不是建议全部上传的清单。代理须按实际入口与下表另行选择建议附件及其职责，保留未上传资料的理由。

定稿时同步修改正文中的输入编号与每单元的实际附件映射。引用整片视频就写`PREVIS-FULL`，引用逐镜片段就列对应编号；不能只改JSON而留下旧正文。`finalize`按单元拒绝正文未映射编号和正文未明示的附件，并在交付记录中保存匹配结果；这不替代对每份参考职责和正文含义的审读。

| 素材 | 应传达的用途 | 选择附件时的注意点 |
| --- | --- | --- |
| 产品图 | 唯一SKU、比例、文字、材质与已见结构事实 | 保留唯一文字/结构权威；多角度是否必要按可见面判断 |
| 主/辅影调图 | 最终色彩、亮暗、光质与材质受光气氛 | 不改变产品身份或抢占布局构图 |
| 完整/逐镜白模视频 | 相机、主体及置景运动，镜头时间与剪辑节奏 | 仅传已实现的部分；不继承白模颜色、代理外形或调试文字 |
| AI布局图 | 必要时辅助空间构型 | 完成Blender后不当然需要上传；入口若只把图当首尾帧，不能宣称它支持纯布局参考 |
| 写作美术资料 | 已转写的材料/形态语言 | 默认仅供作者分析；不能每张图都变成一镜或关键帧 |

输入权限须明确到属性：白模产品长方体只占位，最终仍保留产品图的实际包装；白模视频管相对运动及时间，不管最终色彩和文字；风格图不能覆盖已锁定空间。仅写“不是关键帧”不能证明目标入口会按此使用素材。

## 4. 平台能力与生成单元

在用户指定模型与实际入口时，核查当前的一手文档/工具协议，记录模型、入口、日期和证据。只确认真正可证的单次时长、参考类型与用途、数量、画幅/尺寸、音频及文本计数方式。不为核查而开未授权浏览器、上传客户图或提交付费任务。

平台未指定或能力未知时，输出完整通用正文和中性附件包，写明未映射项；不能声称“已适配”或编造`@图片`等入口标签。用户提供限制可以成为本次输入条件，来源标为用户给定；它不等于官方事实。

镜头是创作结构，生成单元是提交结构，一个单元可含多镜，一个镜头也可跨单元。只有真实入口能力要求时才分段。每个单元保留全片镜号、全片区间与本地时间，完整重述产品和参考权限，明确局部上传映射、跨段产品状态、动作阶段、相机/动势、光影和声音（若有）；不得依赖“沿用上段”。

额外生成余量与成片保留区间单列，重叠事件在成片只出现一次。实际入口无法同时使用需要的身份/运动参考时，先列具体不相容项并给仍可用的中性包，不默默丢弃关键权威、把布局改成首帧或另造拼图。

## 5. 时间、字数和审读

从实际全片时间线计算总长、逐镜区间和稳定停留。片尾1—1.5秒是默认阅读目标；构图、主姿态和品牌落位之后才计时。声明时间通过不等于画面真的稳定，实际预演还须原速观看。

只对实际提交正文计数，包含标题、全局规则、逐镜文本、标点、字母、数字与换行；创意说明和附件表若也提交，则一并计数。用户指定上限优先，没有上限时不硬套5500—6000字符。按入口计数单位检查；未知单位同时记录Unicode码点和UTF-16长度并留余量，不凑满上限。

审读顺序：产品和参考事实 → 核心事件与信息递进 → 相机/主体/光影的因果 → 物量和状态 → 每个切点 → 总时长与落版 → 平台映射与完整可复制性。不能因关键词或字段齐全称为导演合格；字数校验不证明标签正确生成。

## 6. 可直接交付的包

默认交付短创意说明、素材/附件表、AI布局图与结构设计、逐镜及完整白模预演、完整提示词、版本哈希与复现入口。机器契约、检查日志和限制报告作为附件，不混入广告正文。所有客户资料和生成媒体保存在业务目录，不进公共Skill包。

证据报告分别列静态/脚本、真实AI布局、几何/动画技术、原速播放与视觉、最终视频生成、用户验收。未做的项写未做，不能合并成“整条生产流程已验证”。fixture只支持其明确测试的技术机制。

执行者自评与中性产物清单分开。中性清单给实际版本、文件与可复现步骤；自评解释取舍、问题和已接触结论，不能冒充独立验收。交付中简述实际检查内容和待用户审阅点，不自行提升候选状态。
