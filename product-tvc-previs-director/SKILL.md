# 产品广告美术与预演导演

把产品资料变成有依据的美术置景、可检查的多镜头预演和可直接使用的提示词。默认中文、15秒、9:16，通常9—12镜；用户的时长、画幅、镜数、模板、审阅节点和锁定内容优先。镜头长短按信息与动作分配，主布局通常2—4套、多机位复用；这两个范围是规划起点，不是数量门槛。

本包独立完成分析、设计、生成布局图、后台预演和提示词编译，不要求先运行其他Skill或让用户自己生布局图。图像工具负责生成，代理负责美术选择与修正，本包Python负责可重复的场景、动画、渲染、合成和证据。默认交付提示词与素材，不自动提交最终视频生成任务。

## 使用边界与按需阅读

先识别本次授权。完整流程已获授权时持续推进；用户只要求讨论、准备、提示词或离线测试时保留该停止点，不把阶段成果称为全流程完成。客户原图只读，生产文件和工具输出放本次业务目录，不能写入Skill安装目录或公开源码。每次调用图像或外部服务前遵守当次费用、上传与隐私范围；开发测试授权不能扩张为客户素材生成授权。

- 分析产品、选择美术与制作布局图时，读[美术与输入权威](references/art-direction.md)。
- 规划镜头、焦段、运动、灯光或修正预演时，读[摄影、动态与剪辑](references/cinematography.md)。
- 执行本包脚本前，读[运行契约](references/runtime-contract.md)；按当前环境约定使用Blender后台入口，默认不打开桌面。
- 根据实际预演写正文、分配附件或适配平台时，读[提示词与交付](references/prompt-writing.md)，使用[正文模板](assets/prompt-template.md)。

方法、候选参数和模板服务当前产品，不逐项堆砌。无需每次做参考研究；仅在事实或目标入口能力有实际缺口时核查对应一手来源。Runway是可选工具，不是前置依赖；使用当前可用的原生图像生成工具，不猜测其未公开的模型型号。

## 1. 看清输入，锁定事实与职责

实际查看全部产品图和参考图；需要文字依据时打开原图或局部。建立简短素材表，记录文件、哈希、尺寸、用途、SKU、状态、实例与可辨认事实。产品图管身份、可见结构、材质和文字；影调图管色系、亮暗、光质和气氛；设计资料管被指定的美术属性。多张视角不增加实例，不把同款状态当新SKU。

选择清晰正面作为文字主权威，不猜模糊小字、内部机构、成分或功效。冲突按属性定位，保留其他有效设计。无法读取的输入如实标记，先做不依赖缺口的工作；关键身份事实不可替代时才请求具体缺失资料。

## 2. 形成产品依据明确的美术与镜头方案

从形态、表面、包装节奏、可证实材料/动作与用户意图中选核心视觉事件。内部比较少量不同美术路径并自动选择，说明每种主要元素与当前产品的关系、在镜头中做什么。抽象隐喻可以成立，但不能冒充配方或功效证据；不套用“护肤必水滴、彩妆必花瓣”，也不强迫空背景。

先排信息递进与能量，再确定镜数。每镜写“先看什么 → 发生什么 → 切出留下什么”，分开相机、产品/料体/置景和光影的运动。为品牌辨认安排局部窗口；从总时长中预留片尾1—1.5秒真实稳定，先完成入场、景别变化、主姿态与品牌落位再开始计时。

按独立空间和可复用状态分配布局ID。相同置景的全景、侧面、微距可共享一套空间；构型、关键遮挡或主要元素关系实质改变才增加布局。必要特写增加最低限度局部几何，不把每镜都变成一次生图任务。

## 3. AI生成布局图，同时给出可执行空间设计

这一步是完整流程的必要产物，不能用口头设计、任意参考图或Blender技术fixture替代。为每套布局调用已授权图像工具生成白模/中性布局图；代理提供产品占位、置景层次、遮挡、负空间与布局机位，实际查看结果并在授权范围内修正。用户提供产品图后由代理完成这一步，不把生成任务退回给用户。

白模图保留置景设计，用长方体、圆柱、球体等代替产品细模；不花成本复制包装。图像生成前后同步维护结构设计：对象ID、形状、相对尺寸、坐标、前中后层、遮挡关系、布局相机及目标画面关系。单张图不能唯一恢复3D，无法判定的深度标为设计选择，并通过后续机位检查。

布局图只管空间关系；它不改产品事实，不决定最终影调，不自动成为视频首帧、尾帧或每镜必须经过的关键帧。若本次授权不含生图或图像工具不可用，交付已完成的设计与明确缺口，完整布局阶段保持未完成；不得伪造已生成记录。

## 4. 在后台搭建，先校正构图再做动画

先以`prepare --mode layout`建立独立布局预览lane，经后台MCP只渲染布局静帧，完成实际对照与修正后记录哈希绑定的layout review；再以`prepare --mode build --layout-review`建立新的动画lane。真实业务不能跳过布局对照直接渲全片，代理自检不自动增加用户审批节点。

输入只读；每个lane的可写blend、输出、缓存、临时目录和日志互相独立。其他后台Blender存在不构成停工理由；仅真实可写资源冲突需要协调。先检查当前资源，再决定预览分辨率、设备与批次。

摄影从信息目的与景别开始，随后选择传感器、焦段、机位、朝向和距离。24—35、50—85、90—120mm只是不同观察目的的候选，不是固定焦段表；不把距离设成所有镜头共用常数。用主体画面占比、标签位置、安全范围与遮挡关系校正布局机位，把后台预览和对应AI布局图实际并看；改空间、相机或图中不可实现的关系后更新对应版本。

简单几何仅保证占位、可见边界和运动精度。镜头需要真实轮廓、部件动作或接触时，补最少的相关几何并标记剩余差异，不能宣称与真实产品精确一致。布局对照合格只说明声明的构图关系可用，不证明真实材质、产品文字或AI美术质量。

产品采用基本体不等于美术只准使用基本体。弧面、折面、通道等置景可用本包的低模mesh顶点/面通路实现；按实际能力设计最低必要几何。不能先生成有设计的布局，再因脚本方便把主要装置偷偷删成几块方块。

## 5. 多镜动画、完整合成与实际查看

将空间设计落到相机路径、目标朝向、主体/置景动作和速度曲线。保持明显的空间与景别发展，避免相机完全抵消主体运动；运动峰值按主信息错开，不把每镜都写成同一匀速环绕或推近。以脚本实现重复机制，不能每次临时拼一套未校验Python。

先低成本渲染受影响镜头及切点，检查朝向翻转、穿插、画外丢失、焦段/占比和稳定落版；修正后重新渲染受影响部分。合成完整预演后实际原速播放，检查节奏、速度、镜间状态与停留。静帧、帧数、曲线读回和文件生成均不能替代播放；不能播放时记录未验证，不称运动丝滑。预演默认无声；声音有明确需求才纳入并检查同步。

## 6. 从实际预演编译提示词与附件

冻结实际使用的契约、布局版本、blend、逐镜视频和合成视频及其哈希，再用本包编译器提取真实镜号、时间、焦段和运动设计。文字必须与实际预演一致，不能把失败动作或尚未实现的原方案写成已预演事实；未在白模实现的最终材质、光影和物性表现明确属于外观设计责任。

保留正文模板的层级与自然语言逐镜写法，填入本产品事实、空间、影调、运动与切点，删除无关示例而不删除重要信息。白模视频负责相机/主体运动及时序，产品图负责身份，影调图负责最终外观。编译后的正文仍须语义审读，哈希与机械检查不能证明导演质量。

编译器实际读取本包唯一正文模板并按镜头展开。只调整最终文案、字符长度或平台单元/附件映射时，使用`finalize`绑定已冻结媒体并输出新版本；不为这些文本工作重复渲染。实际机位、动作、切点、时长或布局改变时仍须新lane重做受影响预演，不能靠改定稿记录使旧媒体变成新设计。

目标模型和入口已指定时核实实际时长、参考类型/职责、数量、画幅与文本限制。镜头数不等于生成任务数。未知能力时交付通用正文和中性附件表；不得编造上传标签，或仅凭一句“不是关键帧”断言平台会按指定用途使用图像。最终视频生成另需明确任务授权。

## 7. 交付与证据层级

交付可直接使用的结果：简短创意说明、素材与附件对应表、AI布局图及结构设计、完整预演与逐镜文件、完整提示词、版本/哈希与复现入口、尚未验证项。最终提示词不夹带内部比较、审计词汇或运行日志。保留用户指定审阅节点，修正本次变更影响的相关接口。

逐项说明证据，不合并为一个“全流程通过”：

| 层级 | 需要的实际证据 | 不能据此推出 |
| --- | --- | --- |
| 静态与脚本 | 包验证、契约拒绝非法输入、脚本实际运行 | 美术、运动或生成效果优秀 |
| 真实AI布局 | 已生成图、生成输入记录、实际查看和修正 | 精确3D重建或用户批准 |
| 几何与动画技术 | 后台场景/曲线读回、渲染、布局对照、时间/帧数 | 原速节奏或最终材质合格 |
| 预演播放与视觉 | 实际原速查看受影响片段及完整预演的记录 | 最终视频模型已执行 |
| 最终视频 | 实际生成结果、完整回看与相关质检 | 用户已验收 |
| 用户验收 | 用户对明确版本的接受 | 未审版本也获批准 |

合成fixture只能用于标明范围的技术测试，不能当真实AI布局或客户制作案例。本Skill作者的检查属于自检；需要独立验收时保留原始要求、实际版本与未测项，先首评后对照执行者自评，不冒称独立首评。
