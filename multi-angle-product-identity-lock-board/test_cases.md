# Multi-Angle Product Identity Lock Board: Acceptance Scenarios

These cases guide maintenance and actual task review. They are not a runtime
receipt or a requirement to run a separate testing project during generation.

| Input or event | Expected behavior |
| --- | --- |
| One simple opaque product, no subagent slot or Codex database | Generate with the available image tool directly. |
| Exact packaging copy, refractive liquid, folding mechanism, or state change is central | Route to the appropriate specialist workflow; do not certify it through this low-risk board. |
| Product reference plus sample board | Product controls identity; sample controls layout only. |
| Source exists as a supported conversation image | Use that reference mechanism after inspection; no fabricated filesystem path. |
| Completed image is available in the current turn | Inspect it and deliver the complete prompt pair without an artificial continuation request. |
| Actual tool result is pending or the host ends the turn | Preserve the attempt and resume only when its real result is available. |
| Multiple tasks create images concurrently | Select the image returned for this call, not the newest file. |
| One of six views is duplicated or cropped | Fail content QA or repair the dominant defect. |
| Rear or underside structure lacks source evidence | Mark uncertainty; do not infer hidden engineering truth from generated pixels. |
| Nearby built-in ratio with correct six-view content | Record dimensions; no repair solely for ratio and no invented native provenance. |
| A repair follows a failed attempt | Preserve both attempts, accept one, and deliver only that accepted image's generation prompt. |
| Two focused repairs still fail | Report the specific failure; do not loop or declare approval. |
| Enhancement prompt describes a defect never observed | Remove the unsupported diagnosis; preserve actual board and source roles. |
| Final prompt bytes or hash differ | Report integrity failure; do not rebuild the old prompt from memory. |
| User requests complete prompts as files | Deliver complete saved files and their hashes in the requested format. |
| External provider lacks verified 4K controls | Prepared handoff is not a submitted or verified 4K result. |
| An external upscale reaches 3840x2160 | It does not establish Codex-native 4K provenance. |
| QA passes but no production approval exists | Do not write Canon or grant material/label authority to this geometry-only board. |
| User approves a source-limited board whose QA remains conditional | Deliver it with limits; approval does not replace the passed-QA gate for terminal geometry authority. |
| Board is visible but its bytes are unavailable, even with approval and valid prompt hashes | No hash-bound terminal handoff; the usable reviewed board can still be delivered with that limitation. |
| An accepted board file is replaced before handoff | Recompute its hash and require binding to the inspected accepted attempt; old QA and prompt hashes cannot authorize different bytes. |
| External result is labeled 4K but requested 16:9 profile evidence is missing | Keep it unverified and record the gap; a requested setting or provider label is not verification. |
| Returned file has confirmed resolution controls but duplicates a view or changes a seam | Reject the external result for fidelity/topology failure despite valid resolution evidence. |
| Returned file, full source bundle, observed dimensions/ratio, 16:9/4K evidence and six-view fidelity all pass | External verification may pass; it still cannot supply native provenance, production approval, label-copy authority or material-behavior authority. |

Default delivery contains the board, complete generation/enhancement prompts,
both hashes, concise QA, observed dimensions, and external readiness. Actual
visual correctness requires inspecting generated images; static package checks
cannot certify model behavior or product fidelity.
