# 视频提示词逐镜校对

在生成之前发现提示词的导演设计缺陷，用多条真实参考片帮助用户修正。重点是每个镜头在时间中的事件、景别、空间与声音关系。审查结论必须定位原文；具体生成效果仍需实际视频验证。

## 触发与边界

- 用户提交待用视频生成提示词时，主动进入本流程，无需另等“请检查”。只有创意想法、尚无提示词时，说明缺少审查对象，不虚构逐镜结论。用户明确限定本轮为翻译、局部文字修改或只读分析时遵守范围。
- 支持产品、人物、剧情、建筑、走秀、音乐视觉等题材和不同供应商；按当前片子的目标选参考与标准，不强套产品广告模板。
- 默认交付诊断、风险与逐镜修正建议。局部示范属于诊断；只有用户要求改稿时才交付完整修订提示词。保留身份、创意、镜数、时长、台词及其他锁定，不自行减镜或换制作路线。
- 不提交视频生成、不上传客户素材、不购买音乐、不新增付费操作。公开参考仅作研究，访问权限不等于素材复用权。
- 本包独立运行。可以借用已有有效参考研究成果，但不要求另一个 Skill、仓库路由或固定机器路径。无需每次审查都运行包维护测试。

## 1. 固定审查对象

实际读完提示词及用户最新纠正，记录本轮版本、总时长、镜数、题材、投放形式、目标观感、参考图/关键帧职责及已知生成入口。用户未指定供应商时先做通用审查；涉及某模型的硬限制再查当前官方资料。

保留原文，为全部镜头分配稳定编号和原文位置。原文有镜号就沿用；没有则按真实镜头边界编号，不能把同一镜内部阶段误数为多个镜头。区分“原文明确”“原文未写”“推断风险”。缺附件时指出依赖，继续可完成的文本部分。

可运行轻量定位器，输出留在当前任务工作目录：

```bash
python scripts/scan_prompt.py "prompt.md" --out "prompt-scan.json"
```

它只定位可疑措辞与显式镜号，保留输入 SHA-256 和行号，结果始终是 `NEEDS_SEMANTIC_REVIEW`。否定句、引用、反例也会命中；必须阅读上下文裁决。没有命中不等于通过，镜号识别不等于完整分镜解析。复用旧扫描前可用 `--expect-sha256 <原摘要>` 核对版本。

## 2. 研究多条相近参考视频

读取 [参考研究与证据](references/reference-research.md)。按表达目标、题材/主体、片长和节奏形式选择全球范围内合适的成片。默认研究 **3–5 条不同作品**；用户给定数量时照办。“多条”至少两条，同片转载、裁切和同系列近重复不能冒充不同样本。

实际播放并听音，记录作品/版本、来源、观看范围与时间码。分析结构、景别和内容类别占比、镜头时长、剪切点、节奏、音乐发展、转场、镜内景别变化与运镜机制；每条参考都说明与本需求的关系及可迁移机制。找不到完全同题材时保留最接近的参考，明示不匹配点，不能用无关作品凑数。

完整看片与片段分析分开；静帧、播放器截图、网页介绍、字幕和波形都不能单独证明运动或音乐已核实。音频无法实际听辨时音乐分析记为未验证。优先寻找可访问的原发布或合法替代来源；尝试合理替代后仍缺证据则交付“文本初审，参考研究未完成”，列具体缺口，不能编造观看或宣布完整审查通过。

## 3. 逐镜审查

读取 [逐镜判据与示例](references/shot-review.md)，覆盖每一镜，包括未发现明显问题的镜头。至少检查：

- **镜头任务与事件**：这一镜让观众发现什么；主体/材料发生什么；开头、过程、结尾是否不同；前后镜是否重复同一信息。
- **弱运镜硬检查**：实际镜头指令中的“微横移”“小幅升高”“轻后撤”“缓慢升高”及实质相同的软弱写法均需修正。只换形容词或删禁词不足以解决问题。引用这些词来禁止它们不算违规。
- **镜内景别变化**：每镜都检查起始景别 → 结束景别、主体占画尺度和变化路径。默认要求可感知变化，**优先明显、大幅度变化**。全片有远景和特写不能替代单镜内部的变化；同景别换角度、主体轻晃或背景漂移也不能算大幅景别变化。
- **运动可执行性**：路径、幅度、方向、速度发展和时长能否共同成立；区分摄影机位移、镜头变焦、主体运动及二维裁切。大幅变化应服务揭示、关系、动作或情绪；不机械追求最高速度、每镜极端变焦或同时堆满全部轴向运动。
- **切点与衔接**：在什么事件/动作/音乐位置切、下一镜如何承接，视线、方向、动作和空间关系是否清楚；转场必须有前后画面条件，不能只报效果名称。
- **约束与模型风险**：关键帧是否锁死视点/尺度/动作，图像职责与摄影指令是否冲突；镜数、时段和复杂度是否可能导致漏镜、并镜、跳变、形变或动作无法完成。风险用条件和依据表达，不声称必然发生。

无景别变化或变化不明须逐镜指出。用户明确锁定静止镜、固定机位、定格落版时保留锁定，报告与审查偏好的冲突或明确例外；不得偷偷破坏锁定，也不得自行把“最好大幅”升级成每镜必须极端变焦。慢速度与小幅度分别判断；一条慢速但跨度明确的长推进可有充分变化，不能因“慢”字一律否决。

## 4. 检查全片及音乐

将逐镜发现放回时间线：结构推进、主体/环境/细节等内容占比、景别分布、镜长分布、同类运镜连续重复、剪切密度与高潮/收束。区分按镜数计算与按时长计算的比例。明确缺少的时间信息，不捏造百分比或理想镜头配额。

音乐是必查项。未写音乐设计判为缺失；仅“高级、震撼、氛围感 BGM”判为不足。检查风格/音色、节奏或拍感、进入与退出、段落发展、重音/停顿，以及动作、剪切、高潮和结尾的对应关系。不是每个切点都必须踩拍。音效、环境声、旁白不能自动替代音乐设计。

用户明确要求无音乐时尊重并记录；有对白时还检查音乐是否遮挡信息。区分本次生成入口能直接执行的声音指令和后期声音方案，能力未知时核实或标明，不把文本写入当已生成声音。

## 5. 交付并复核

按 [报告格式与完成条件](references/report-format.md) 给出简洁、可执行的报告：最重要问题 → 参考研究依据 → 全部镜头审查 → 全片/音乐问题 → 修正优先级与局部示范 → 未验证项。

每项诊断连接原文位置、具体缺陷、后果/风险、参考或约束依据和可执行修正。修正应写出起止景别与事件、路径、时间和切点；“运镜再大一点”“更电影感”不能作为完成的建议。

区分必须修改、优先改善、生成风险和待核实。不要用综合分数掩盖弱运镜、无景别变化或音乐缺失，不因扫描零命中而放行。检查建议是否互相矛盾，是否保留所有锁定。文本审查、参考片实际观看、自检和用户接受分别说明；不能保证生成结果。

用户要求修订时复查受影响镜头和邻接剪切/音乐时间，必要时更新参考研究。实际生成反馈到来后，关联原提示词和视频版本，将预判与实片对照，再修正；静帧不能结案运动问题。
