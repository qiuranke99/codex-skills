## 1. 为什么需要这份手册

“描述结果，让模型在 Blender 里创建，查看截图，再自行修正”是有效的
工作方式，但它只解决了界面操作和可见错误，不自动解决以下问题：

- 产品结构是否来自真实证据；
- 隐藏零件、连接关系、比例和枢轴是否被发明；
- 单个好看的画面是否掩盖脏拓扑、错误层级或破坏性修改；
- 关键帧之间的运动是否有重量、节奏和连续性；
- 材质、灯光、色彩管理和采样是否达到最终 CGI 标准；
- 输出究竟是给 AI 模型看的控制参考，还是给客户看的最终像素。

因此，Blender 的价值不只在“模型能操作软件”，而在建立可恢复的
视觉反馈闭环：

```text
构建
  -> 渲染或截图
  -> 对照目标检查
  -> 写入问题账本
  -> 只修一个可解释的问题簇
  -> 回归结构、画面和时间
  -> 保存检查点
  -> 继续下一轮
```

MCP 只是控制入口。成功调用工具、Python 没报错、Blender 没崩溃、
文件成功保存，都不等于作品完成。

对本机用户而言，主要瓶颈已经不是 Blender 界面，而是：

1. 复杂产品证据与真实模型的可靠映射；
2. 结构、画面、运动、材质、交付标准之间的分层验收；
3. 大型源资产与有限 GPU 资源下的可恢复迭代；
4. Blender 输出在 AI 视频链或最终 CGI 链中的明确责任边界。

## 2. 先判断 Blender 在本次任务中的角色

每次开始前必须回答：

> 最终被消费的是 Blender 生成的“控制信息”，还是 Blender 生成的
> “最终像素”？

依据答案为每个镜头选择一条主路线。一个项目可以逐镜头混用不同
路线；一个 Blender 执行单元仍只能有一个主验收路线：

| 路线 | 最终消费者 | Blender 的责任 | 质量上限 |
| --- | --- | --- | --- |
| `DIAGNOSTIC_ONLY` | 人或后续执行者 | 只读检查、定位、报告 | 不产生生产修改 |
| `AI_REFERENCE_PREVIS` | 导演、人类、AI 视频模型 | 结构、构图、镜头、运动意图 | 低清可读，不是成片 |
| `HYBRID_AI_CONTROL` | AI 生成模型与后期 | 身份锚、运动参考、控制通道、合成底座 | 控制精度高，最终像素由混合链完成 |
| `FINAL_CGI_RENDER` | 客户、播出平台、成片时间线 | 资产到最终像素的全部责任 | 必须达到最终交付标准 |

### 最高负担原则

一个任务可以包含多个用途，但只能有一个主验收路线。若最终需要
Blender 直出客户可用画面，则必须采用 `FINAL_CGI_RENDER`，不能因为
前期也会把画面交给 AI 参考而降低验收标准。

若用户尚未明确最终消费者，但现有事实足够推断，Codex 应自行分类并
说明假设。只有不同路线会实质改变成本、画面或交付时才请求选择。

### 逐镜头推荐

- 氛围宽景、抽象过渡、只需运动意图：`AI_REFERENCE_PREVIS` 或轻量
  `HYBRID_AI_CONTROL`；
- 产品中近景、AI 环境或 FX，但产品身份必须稳定：
  `HYBRID_AI_CONTROL` 的锁定产品合成模式；
- Hero 产品、精确结构、Logo、文字、功能声明和必须可重复的镜头：
  `FINAL_CGI_RENDER`。

若 AI 模型需要重绘整个产品，就不能同时承诺严格的产品身份一致性。
高风险产品镜头应让 Blender 保留产品最终像素，只允许 AI 修改事先
声明的背景、环境、气氛或 FX 区域。

### 路线合同

修改场景前记录：

```yaml
shot_id:
route:
final_pixel_owner:
delivery_target:
resolution:
fps:
frame_range:
identity_fidelity:
source_truth:
locked_product_zones:
ai_allowed_zones:
required_outputs:
render_engine_or_provider:
hard_gates:
final_classification_target:
```

以下任一项未知时，不得进入正式制作：最终像素所有者、产品身份精度、
必须准确的 Logo/文字/结构/颜色/功能区域、来源优先级、交付规格，
以及资源不足时的替代执行路径。

## 3. 四条交付路线

### 3.1 `AI_REFERENCE_PREVIS`

用于：

- AI 视频的镜头参考、运镜参考或动作参考；
- 结构可信的白模/Clay+ 动画；
- 产品局部装配、悬浮、爆炸或转台的低清预演；
- 导演审核构图、节奏和可见性。

允许：

- EEVEE、代理几何、语义材质、低分辨率；
- 有界简化，但必须保留目标结构与运动事实；
- 只在合同样帧上做高频迭代。

不证明：

- 最终材质、最终灯光、最终噪声水平；
- 最终拓扑与可交接资产健康；
- 最终合成、调色和客户批准。

### 3.2 `HYBRID_AI_CONTROL`

用于：

- Blender 锁定产品、相机和运动，AI 模型负责外观或最终视频生成；
- 输出关键帧锚、首尾状态、控制视频、深度、法线、对象遮罩、
  Cryptomatte、运动向量或其他 provider 实际支持的控制；
- AI 生成结果再回到合成、产品身份与运动 QA。

关键原则：

- 只输出下游模型真实支持的控制通道；不得把“可能有用”当作绑定能力；
- RGB 参考、身份图、控制通道和镜头合同必须拥有一致的帧号、比例、
  相机和版本；
- AI 结果必须重新接受产品身份、可见动作、物理可信度和连续性检查；
- Blender 控制包完成不等于 AI 生成或最终合成完成。

### 3.3 `FINAL_CGI_RENDER`

用于：

- 产品静帧、广告镜头、动画或完整画面由 Blender 直接产生最终像素；
- 客户将 Blender 渲染作为实际交付，而非方向参考；
- 需要可重复渲染、可合成、可归档和可交接的 CGI 工程。

该路线不能使用 previs 完成标准。它必须增加资产、材质、灯光、
色彩、渲染、合成和最终序列 QA。

### 3.4 `DIAGNOSTIC_ONLY`

用于：

- 读取 `.blend`、FBX、层级、依赖、对象统计或错误日志；
- 检查 MCP、渲染器、插件、资源路径和当前状态；
- 在未获修复授权时只解释根因。

只读检查不授权修改、保存覆盖、安装插件或移动资产。

## 4. 所有路线共享的启动门

### 4.1 目标门

记录：

- 主路线；
- 最终消费者；
- 交付分辨率、帧率、时长、画幅；
- 目标文件和版本位置；
- 哪些内容必须保真，哪些允许近似；
- 完成定义与不可接受状态。

### 4.2 来源与结构证据门

建立证据优先级。复杂产品默认：

```text
真实源模型对象/层级
  > 官方图纸、产品照片、经批准参考
  > 身份规格与标签
  > 生成式诊断图
  > 旧脚本或文字猜测
```

必须区分：

- 已证实结构；
- 可逆推断；
- 不可见或证据不足；
- 禁止补造内容。

看不见的背面、内部、折叠状态或连接方式不得因构图需要而凭空完成。

### 4.3 当前状态门

以本次实际读取为准，验证：

- Blender 版本、渲染引擎和工程单位；
- MCP 或 CLI 是否在当前任务真实可调用；
- 当前文件路径、保存状态、备份和依赖；
- 可用内存、显存、磁盘、预计缓存和渲染时间；
- 插件、字体、贴图、linked library 和外部缓存是否完整。

旧记录只能定位检查项，不能代替现场状态。

### 4.4 非破坏与恢复门

在修改前：

- 解析源文件与目标输出的绝对路径；
- 创建版本化工作副本，不覆盖唯一源文件；
- 对关键输入记录大小、时间或 SHA-256；
- 设定检查点和失败恢复位置；
- 对大型导入、模拟和最终渲染建立进度清单。

### 4.5 资源预算门

先估算场景规模，再选择：

- 交互 Blender MCP；
- 一个或多个写入边界相互隔离的 background Blender lane；
- 轻量代理场景；
- EEVEE 预演；
- Cycles/CPU/外部 GPU 或渲染农场；
- 分层渲染、区域测试和缓存策略。

不得以降低最终质量标准来掩盖本机硬件不足。资源不足时应改变执行
位置、分层或渲染策略，并保留目标标准。

## 5. 持续视觉自检闭环

### 5.1 分阶段构建

不要用一个巨型提示一次性要求完整广告。依次冻结：

1. 结构与尺度；
2. 构图与相机；
3. 运动与时间；
4. 材质与表面；
5. 灯光与反射；
6. FX 与模拟；
7. 渲染与合成。

上一阶段未通过，不得用下一阶段的复杂度掩盖问题。

### 5.2 Maker–Checker 循环

每轮必须产生以下证据：

1. 当前输出截图、样帧或短 playblast；
2. 与目标的差异列表；
3. 差异的可能原因；
4. 本轮允许修改的对象或参数；
5. 修改后对照；
6. 结构、画面和时间回归结果；
7. 新检查点路径。

### 5.3 把主观反馈转成可执行变化

| 主观反馈 | 可检查原因 |
| --- | --- |
| 产品显得廉价 | 焦段过广、边缘畸变、塑料高光过硬、表面粗糙度单一、主体占比过小 |
| 动作没有重量 | 匀速插值、无预备与跟随、加减速时间错误、停止无缓冲、接触点漂移 |
| 主体不突出 | 轮廓与背景明度接近、关键结构被遮挡、主高光未定义体积 |
| 画面太普通 | 镜头功能不清、层次不足、光线无叙事、运动只有位移没有节奏 |
| 透明材质看不清 | transmission、IOR、厚度、roughness、内部/外部照明未分离 |

“感觉更高级”不是可验收修改。必须落到可见属性。

### 5.4 视觉量化边界

只有取得真实测量证据时，才能报告遮挡比例、可见长度、轮廓重叠等
数值 PASS。可采用：

- 对象 ID 或材质 ID；
- Cryptomatte；
- 分层 mask；
- 深度与法线；
- 屏幕空间包围盒；
- 像素级分割。

没有这些证据时只能标记 `visual_review_required`。

## 6. 路线 A：AI 镜头参考 Previs

原始流程应升级为：

```text
用途与镜头合同
  -> 结构证据锁定
  -> 非破坏轻量工作代理
  -> Clean Clay 构图
  -> 关键帧视觉修正循环
  -> FX Guide（需要时）
  -> 完整低清 playblast
  -> 时间/运动/碰撞审核
  -> 结构回归
  -> AI 参考输出打包
  -> 保存重开
  -> 最终分类
```

### 6.1 结构与代理

- 保留源层级、局部坐标、真实比例、可动部件和铰链原点；
- 从已确认对象生成轻量工作代理，不反复重新导入巨型源文件；
- 代理简化不得改变镜头可见轮廓、接触关系或运动轴；
- 原始高精模型保持只读。

### 6.2 Clay+ 语义显示

建议：

- 中性灰：真实产品主体；
- 青蓝：生成、粒子、轨迹或过程辅助；
- 橙色：切割、融合或结构变化边界；
- 不透明灰：液体代理网格；
- 灰阶体积：烟雾或体积节奏。

语义颜色服务于阅读，不代表最终材质。

### 6.3 镜头与运动

先锁：

- 镜头功能；
- 相机高度、焦段、距离和目标点；
- 入画、关键状态、出画；
- 主运动、次运动和静止参照；
- 节奏、停顿和切点。

完成关键帧修正后必须渲染完整低清 playblast。只看若干样帧不能证明：

- 插值过程无穿插；
- 镜头速度合理；
- 动作有重量；
- FX 不闪烁；
- 中间帧没有语义遮挡。

### 6.4 AI 参考包

按下游实际需求输出：

- 完整低清参考视频；
- 关键帧 contact sheet；
- 镜头、焦段、帧率、时长、帧区间；
- 目标对象和运动说明；
- 结构锁定与允许变化项；
- 明确标记非最终材质、非最终灯光和非最终 FX。

终态只能是 `draft_lowres_3d_motion_previs` 或
`ai_reference_previs_approved`，不能写成最终渲染。

## 7. 路线 B：AI/CG 混合控制包

流程：

```text
身份与结构合同
  -> 相机/运动 Previs
  -> 首尾与关键状态锚
  -> provider 能力核验
  -> 控制通道渲染
  -> 跨通道帧级一致性验证
  -> AI 生成
  -> 身份/动作/物理/连续性 QA
  -> 合成与修复
  -> 最终分类
```

### 7.1 两种子模式

`FULL_FRAME_REFERENCE_TO_VIDEO`：AI 重绘整帧。适合概念探索和中低
身份风险画面；不适合承诺精确产品轮廓、Logo、文字或机械结构。

`LOCKED_PRODUCT_COMPOSITE`：产品由 Blender 保留最终可见像素；AI
只负责背景、环境、气氛或指定 FX，最后通过遮罩、AOV 和合成汇合。
复杂产品广告默认优先采用这一模式。

### 7.2 输出选择

可能的输出包括：

- RGB Clay 或 Look 参考；
- 深度；
- 世界/相机空间法线；
- 对象或材质遮罩；
- Cryptomatte；
- 运动向量；
- 透明背景产品 pass；
- 阴影、反射或 holdout；
- 首帧、尾帧和中间状态锚；
- 相机与时间元数据。

但“可能输出”不等于“下游能用”。先核实 provider 对格式、帧数、
分辨率、色彩空间和附件数量的真实支持。

### 7.3 一致性门

所有控制输出必须共享：

- 相同 Shot UID 和版本；
- 相同帧号、时长、帧率、画幅；
- 相同相机与裁切；
- 相同对象可见性和运动状态；
- 可追溯的源模型与身份合同。

任意控制通道发生变化，必须声明被失效的下游生成结果。

### 7.4 Provider 交接合同

送生成前锁定：

- provider、模型和版本；
- 提示词、负向限制、参考顺序、槽位和角色；
- seed 或等价可复现参数；
- 时长、分辨率、帧率和色彩要求；
- 锁定产品区域与 AI 允许区域；
- 失败后由 Blender、provider 还是合成负责修复。

没有聊天记录的第二位操作员必须能够仅凭交付包复现提交。

### 7.5 AI 回流验收

AI 结果必须重新检查：

- 产品轮廓、零件数量和左右关系；
- 标识、材质分区和不可变身份；
- 运动方向、接触、重量与因果；
- 相机路径和构图；
- 前后镜头连续性；
- 闪烁、融化、重复零件和纹理漂移。

Blender 包完成时只能标记 `ai_control_package_ready`。AI 生成和合成
通过后才可进入更高一级交付状态。

### 7.6 修复归因与停止条件

- Blender 控制错误：回 Blender 修改并失效旧控制包；
- provider 漂移：修改参考策略、缩短分段或改走锁定产品合成；
- matte、边缘、景深或光影匹配问题：交给合成修复；
- 同一身份漂移连续失败时不得无限重试，应切换到
  `LOCKED_PRODUCT_COMPOSITE` 或 `FINAL_CGI_RENDER`。

## 8. 路线 C：Blender 最终 CGI 直出

这条路线包含 Previs 的全部门，并增加以下生产阶段。

### 8.1 Final Asset Gate

检查并修复：

- 真实尺度、比例和制造逻辑；
- 可见表面的拓扑、法线、平滑与倒角；
- UV、UDIM 或程序坐标策略；
- 命名、集合、父子层级、原点和约束；
- 重复对象、孤立数据、隐藏垃圾和不必要细分；
- 高低模、实例、LOD 或代理切换；
- rig、权重、驱动、碰撞体和模拟拓扑；
- linked library、贴图、字体、缓存和许可证。

单一镜头看起来正确不能代替资产健康。

### 8.2 Material and Lookdev Gate

最终材质必须来自可解释的表面模型：

- 基色不是照明后的照片颜色；
- roughness、specular/IOR、metalness、transmission、coat、厚度和
  法线具有材料依据；
- 纹理比例与真实尺度一致；
- 标签、印刷、接缝、边缘磨损只在证据允许时存在；
- 透明、半透明、金属、涂层、橡胶、织物分别接受高光和透射测试；
- 使用灰球、色卡或批准参考建立比对条件；
- 冻结色彩管理、view transform、曝光和显示条件。

不得把 Clay+ 语义材质当作最终表面。

### 8.3 Lighting and Camera Gate

逐项锁定：

- 镜头功能和目标观看距离；
- 焦段、传感器、畸变、景深和运动模糊；
- key/fill/rim/background/reflection 的各自作用；
- 产品关键结构是否由高光定义；
- 标签、屏幕和透明件是否可读；
- 反射是否遮挡品牌或破坏轮廓；
- 背景与产品的明度、色相和空间分离。

先用低采样 lookdev 检查，再进行目标分辨率区域渲染。不得用高采样
掩盖灯光或材质模型错误。

### 8.4 Animation and Simulation Gate

- 审核完整 playblast，不只审核样帧；
- 检查 F-Curve、速度、加速度、缓入缓出和停顿；
- 检查接触、碰撞、穿插、轮胎/履带/关节等运动学；
- 模拟使用版本化缓存，记录种子、步长和依赖；
- 镜头运动、景深、运动模糊与主体动作共同审核；
- 对循环、转场和剪辑点做首尾状态验证。

### 8.5 最终分辨率代表帧门

全序列正式渲染前，按最难帧、最亮帧、最暗帧、运动最大帧和 FX
最重帧建立风险覆盖矩阵。每个适用风险类别至少选择一帧；同一帧可以
覆盖多个类别，但必须在矩阵中显式标明。某类别确实不适用时，必须在
路线合同中预先声明原因和证据，不得在验收失败后临时标为 `N/A`。

所有选定代表帧都必须以最终分辨率、最终材质、最终灯光和最终渲染
设置完成：

- samples/噪声 wedge；
- 去噪 A/B；
- 透明、体积、阴影、焦散、motion blur 和 DOF 测试；
- 显存/RAM 峰值；
- 单帧时间与全片预算估算。

所有选定代表帧和全部适用风险类别必须通过；任一选定帧失败都阻断
正式全序列渲染。低清 EEVEE 或 viewport preview 不能代替该门。

### 8.6 Render Engineering Gate

根据最终目标选择 EEVEE 或 Cycles，而不是按习惯选择。

必须冻结：

- Blender 与渲染引擎版本；
- 设备与失败回退策略；
- 分辨率、帧率、overscan 和 pixel aspect；
- 采样、噪声阈值、bounce、clamp、caustics 和 denoise；
- motion blur、DOF、volumes、hair 和 transparency；
- 色彩空间、view transform 和输出编码；
- AOV、Cryptomatte、Z、normal、vector、shadow、reflection 等合成 pass；
- 输出目录、命名、断点续渲和磁盘预算。

正式动画优先输出适合合成的图像序列，而不是直接把唯一结果编码成
有损视频。根据合成要求选择 OpenEXR 半浮点/多层或其他明确格式。

### 8.7 Final Pixel Gate

在目标显示条件和目标分辨率检查：

- 噪声、fireflies、闪烁和 denoise 拖影；
- 锯齿、透明边缘、景深边缘和 motion blur；
- 贴图缺失、UV 跳变、法线错误、模拟爆炸和穿插；
- 色彩空间、gamma、黑位、峰值和压缩；
- 帧缺失、重复、顺序、时长和音画要求；
- 品牌、产品身份、文字和法规内容。

完成自动全序列检查后，仍需对首帧、尾帧、剪辑点、运动峰值、
材质高风险帧和随机样帧做人工目视。

### 8.8 Compositing and Master Gate

若最终画面需要合成：

- 保存原始线性渲染与可重建合成工程；
- 记录每个 pass、grade、glow、grain、denoise、retime 和修复；
- 保持产品身份和标签不被后期破坏；
- 输出审片版和最终母版；
- 对母版重新执行时长、分辨率、帧率、色彩和播放验证。

仅关闭并重开本 lane 自有的 Blender 实例，从最终交付场景执行冷重开，
验证贴图、HDRI、字体、LUT、linked library 和模拟缓存均可解析；不得为
完成本 lane 的冷重开而关闭、终止或干扰其他 lane 的 Blender 进程或 MCP
会话。重新渲染至少一个已批准代表帧，并与批准结果比较。仅在原进程内
保存后读取不构成冷重开验收。

终态先为 `final_cgi_render_candidate`；只有 8.1 至 8.8 的全部适用门
均为 `PASS`，才允许 `final_cgi_render_approved`。这显式包括 Final
Asset、Lookdev、Lighting and Camera、Animation and Simulation、
最终分辨率代表帧、Render Engineering、Final Pixel、Compositing and
Master（含冷重开与代表帧复渲）。任何 `N/A` 必须已在路线合同中预先
声明并有证据，不得在终态升级时临时豁免。

## 9. 路线 D：只读诊断

流程：

```text
确认只读范围
  -> 读取版本/场景/依赖/日志
  -> 建立证据
  -> 解释根因与影响
  -> 给出修复选项和验证方法
  -> 停止
```

用户只要求诊断时，不执行修复。可运行不会改变状态的场景摘要、
依赖检查、渲染配置读取和日志检查。

### 9.1 原流程的适用边界

| 原步骤 | AI Reference Previs | Hybrid AI Control | Final CGI Render |
| --- | --- | --- | --- |
| 结构证据锁定 | 必须；允许有界代理 | 还需稳定 ID、mask、UV/normal | 还需最终拓扑、UV、材质、rig、反射/GI 几何 |
| 低清构图 | 足以进入探索 | 必须保持所有控制通道一致 | 还需最终画幅、overscan、DOF、畸变、motion blur |
| 关键帧视觉修正 | 检查结构、构图、遮挡 | 增加 AI 漂移与锁定区域比较 | 增加材质、灯光、噪声、反射和最终像素 |
| 完整低清 playblast | 核心验收 | 还需生成结果全时域 QA | 必须有，但完全不能替代最终渲染测试 |
| 时间/运动审核 | 节奏、穿插、镜头速度 | 增加控制对齐、闪烁和漂移 | 增加子帧、缓存、motion blur 和渲染闪烁 |
| 结构回归 | 对比对象与变换 | 增加通道、相机、帧对齐 | 增加材质、AOV、颜色、缓存和渲染设置 |
| 保存重开 | 验证场景、相机、约束 | 增加控制包与 provider 合同 | 增加全部依赖、缓存和冷重开重渲 |
| 最终分类 | 只能批准 Previs | 只能批准控制包或混合母版 | 最终像素、合成和交付 QA 后才可批准 |

## 10. 五条独立验收轴

任何制作路线都应分别报告：

### A. 结构真实性

- 来源、身份、零件、层级、尺度、枢轴、相对变换；
- 是否存在未经证实的补造或型号混用。

### B. 视觉正确性

- 构图、轮廓、遮挡、焦段、材质响应、灯光和品牌可读性；
- 是否有截图/渲染对照与问题账本。

### C. 时间与物理

- 完整序列、运动曲线、重量、碰撞、因果、镜头节奏和连续性；
- 是否只看了样帧。

### D. 资产与工程健康

- 拓扑、依赖、命名、缓存、插件、版本、可重开、可移交；
- 是否只能在当前机器偶然运行。

### E. 下游交付就绪

- 输出格式、色彩、通道、元数据、版本和消费者能力是否匹配；
- 是否把上游包完成误报成下游最终完成。

五轴必须分别给出 `pass`、`partial`、`blocked` 或 `not_applicable`，
不得以一轴的 PASS 覆盖其他轴。

## 11. 本机资源与工具策略

最近一次验证基线仅用于定位检查项，不是永久事实：

- Blender 5.2 LTS；
- Blender Lab 官方 Blender MCP；
- 可进行场景摘要、对象检查、窗口/区域截图、viewport render、
  Python 执行和后台 CLI 检查；
- 48GB RAM、GTX 1060 3GB；
- EEVEE 适合日常 previs；
- 大型最终 Cycles、体积、复杂透明/毛发和高分辨率序列可能需要
  CPU、分层、外部 GPU 或渲染农场。

每次任务仍必须重新验证当前版本、工具发现、端口、设备和磁盘。

### 11.1 交互 MCP

适合：

- 当前打开场景的可视检查；
- 截图、对象聚焦、局部编辑；
- 快速 maker-checker 循环；
- 需要 UI 上下文的操作。

### 11.2 Background Blender

适合：

- 大型导入；
- 批量、可复现修改；
- 渲染与验证脚本；
- 保存后独立重开检查；
- 当前 MCP 未在任务中热加载时的受控替代路径。

默认允许同一项目或不同项目中的多个 background Blender lane 并行。
禁止创建、服从或等待项目级／机器级 lock、lockfile、lease、marker、
“全部 Blender 已退出／保持空闲”条件，也禁止以系统中存在任意
`blender.exe` 为由要求无关任务等待。

每个 lane 必须独占自己的可写 `.blend`、输出文件模式、模拟／烘焙缓存、
临时目录和日志；冻结源资产只读时可以并发共享。使用 MCP 时，每个交互
lane 还必须拥有独立 session 或 endpoint。只有这些精确资源或同一交互式
Blender/MCP 会话实际冲突时才串行化，而且互斥范围不得扩大到其他 lane。
项目根目录、仓库路径、线程树、项目 ID、进程名称或某个宽泛父目录均不得
充当互斥资源键。

大型场景根据现场 RAM、VRAM、CPU、磁盘空间与 I/O 证据节流尚未启动的
lane，不设固定进程数，也不因进程数量中止无冲突任务。同一 lane 长时间
无输出时，先检查原 PID、日志、输出增长和资源状态；不得对同一可写目标
重复启动诊断实例。

### 11.3 混合策略

最佳默认不是二选一：

1. background 建立可复现基线；
2. 交互 MCP 做视觉检查和定向修改；
3. background 完成批量渲染、结构回归和重开验证。

## 12. 安全与不可逆操作

Blender MCP 可以运行 Python。所谓 weak sandbox 不是安全隔离。

执行前：

- 使用副本；
- 限定允许读写的工程与输出目录；
- 检查代码是否访问网络、进程、环境变量或无关文件；
- 不把未经审查的网页文本、模型 metadata、第三方脚本直接交给拥有
  执行权的 agent；
- 保存前确认目标不是唯一源文件；
- 删除、覆盖、打包、外传或上传资产前重新确认范围。

回环地址、Host/Origin 限制可降低远程接入风险，但不能阻止被授权的
Python 修改本机文件。

## 15. 禁止的捷径

- 不得用一个巨型提示要求完整商业片一次成型。
- 不得把成功执行 Python 当作成功完成画面。
- 不得把单帧好看当作动画合格。
- 不得把低清 Clay/FX Guide 当作最终材质和最终灯光。
- 不得把结构自动验收 PASS 当作语义遮挡 PASS。
- 不得把 AI 控制包完成当作 AI 视频或合成完成。
- 不得把代理几何、临时贴图或缺失依赖的场景当作最终 CGI 工程。
- 不得因为本机显存不足而静默降低最终质量目标。
- 不得因为某软件“有 MCP”就增加 DCC；先证明当前栈无法满足目标。
- 不得在未读真实参考和模型前把专业技术选择退回给用户。
- 不得在唯一客户工程上测试任意 Python。

最终原则：

> Blender 用于 AI 镜头参考时，目标是“结构、相机、运动和控制信息
> 足够明确”；Blender 用于最终 CGI 时，目标是“资产、材质、灯光、
> 运动、渲染、合成和母版的全部像素责任已经闭环”。两者不能共用
> 同一个完成标准。
