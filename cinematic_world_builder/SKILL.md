# Cinematic World Builder / 电影世界生成器

## Standalone Runtime Contract

Run directly from this package. The world name, continuity concept, and visual prompts form a portable text artifact. No release manager, sibling Skill, or downstream project is required. A supplied brief or continuity document is an input constraint.

本 Skill 默认交付世界构建提示词。只有用户要求实际出图时，才在完成提示后使用当前可用、已获授权的生图工具；未生成图片时不得声称已经出图。

## 工作原则

- 保留核心主题、不可替换元素、时代、文化、科技水平、主体身份和用户分配的参考职责。用户指定的数量、方面、风格、构图和输出格式优先于本文默认值。
- 简略输入也能直接发展成完整世界。只询问会改变核心世界或素材身份的关键歧义；普通地理、材料和镜头选择由上下文合理补全。
- 有参考图时先检查实际图像，区分可见事实与创作扩展。不根据文件名猜测内容；不能读取时仅使用用户文字，不声称看过。除非要求复刻，以明确分配的属性启发世界，不机械复制图像。
- 默认采用电影现实主义、电影静态画面、可信材料和观察式镜头。用户指定动画、CGI、洁净数字影像、对称或居中构图等方向时，遵循该方向，不附加冲突负面词。
- 世界应通过具体场景成立。不要默认扩写历史年表、政治制度或物种百科；用户要求这些内容时再提供。

## 执行

1. 用一句话确定不能丢失的主题，提取已锁定事实与风格。
2. 建立共享的连续性：地理、气候、材料、服饰或身体覆盖、建筑语言、工具与技术、动物关系、劳动、符号、信仰痕迹和社会压力。只选择与输入有关的维度。
3. 按下列九个方面组织默认输出，每个方面承担不同叙事任务。用户指定其他数量或方面时，按其要求选择、合并或增加；不要为凑默认结构添加无关生物、人物或灾难。
4. 写出可拍摄的场景和可见行动，检查同一世界内的连续性、叙事区分和镜头变化，然后交付。

## 必须生成的 9 个方面

用户未另定方面与数量时，必须正好生成以下 9 个方面，按此顺序：

1. 居民
2. 动物
3. 建筑
4. 景观
5. 日常生活
6. 旅行或运动
7. 声音或文化
8. 权力或强度
9. 肖像

## 方面定义

| 方面 | 独立叙事任务 | 可见表达与默认避让 |
| --- | --- | --- |
| 居民 | 谁住在这里，如何存在 | 用身份、姿态、身体覆盖、劳动和环境关系呈现；避免角色表、物种阵列和英雄摆拍。 |
| 动物 | 哪些生命与此地共存 | 展示工作、迁徙、照料、捕猎或敬畏，也可通过足迹、巢穴、呼吸、阴影等痕迹呈现；避免孤立标本。 |
| 建筑 | 如何庇护、聚集、统治、隐藏或记忆 | 展示空间被使用的方式、工具、织物、通道、修补和光线；避免脱离生活的建筑效果图。 |
| 景观 | 土地如何塑造文明 | 让地理、气候和地形主导，以路径、作物、废墟、烟、动物或远处身影建立尺度；避免空泛奇观。 |
| 日常生活 | 什么普通行为反复发生 | 食物、手工、洗涤、修理、贸易、家庭、训练或玩耍；保留日常强度，不自动升级为灾难或盛大仪式。 |
| 旅行或运动 | 如何穿越地方之间的距离 | 写清主体、起点、方向、地形或阻力、负重和到达状态；避免无行动站立或交通工具目录。 |
| 声音或文化 | 什么被聆听、记住或表演 | 通过乐器、工具敲击、舞蹈、聆听、口述、回声空间或沉默中的反应，让声音与意义可见；避免说明牌。 |
| 权力或强度 | 什么压力考验世界 | 使用世界逻辑支持的权威、稀缺、危险劳动、速度、天气、对峙或危机；不凭空添加战争、爆炸和英雄动作。 |
| 肖像 | 什么私人瞬间承载情感 | 用目光、呼吸、手势、局部脸、磨损物件、聆听或亲密关系呈现；默认避免证件照和时装摆拍。 |

## 场景与摄影

每条提示写成一个完整段落，说明主体位置、环境、服饰或身体覆盖、材料、光线、必要天气、相机距离与构图，以及此刻正在发生的动作。前景、中景、背景、遮挡、负空间和景深按镜头用途选择，不机械填槽。

镜头变化服务于叙事：低角度与前景尺度表现重量或敬畏；高角度与负空间表现孤立、地理和秩序；近景、手部和浅景深表现劳动与情感；肩后、门框和障碍表现秘密或见证。避免所有方面都落成同一种中远景。

用具体材料、环境使用方式和行为建立文化，保持时代、气候、颜色与技术逻辑一致。自然光、实用光、颗粒、雾、尘土、磨损和运动模糊都是可选手段，不能每图强加，也不能违背干净或明亮的用户要求。抽象词如“史诗”“高级”“震撼”应由可见事实支撑。

默认追求电影场景，避免海报、角色表、概念板、目录、黑条和无意添加的文字；用户明确要求相应形式时，以其要求为准。

## 默认负面尾句

仅在默认电影写实风格适用时，可用以下尾句。用户的风格或构图与其中某项冲突时，删去冲突项；不要用负面尾句覆盖创作要求。

```text
无干净数字锐度，无CGI外观，无海报构图，无居中肖像，无黑条
```

## 输出

默认给出一个诗意世界名、2–3 句世界概念，以及九个方面。每个方面只包含标题、一句简短视觉化的“世界构建笔记”和一段完整“提示”。用户要求仅正文、指定语言或自有模板时，使用其格式。

## 自检

- 默认是否正好 9 个方面；用户另定时是否符合实际要求。
- 世界名称、概念与每个方面的笔记和提示是否齐全。
- 各方面是否具有独立叙事目的、可见行动与明确镜头。
- 身份、材料、气候、地理、建筑、服饰、动物和文化是否连续。
- 是否避免无意重复机位、无关设定、海报或目录倾向。
- 风格与负面词是否兼容，是否保留了用户的核心意图。

维护本包时运行 `python -B scripts/test_contract.py`；该检查只验证包结构与默认方面表，不证明创作质量。
