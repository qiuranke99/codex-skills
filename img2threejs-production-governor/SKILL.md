# img2threejs Production Governor

Use this Skill as the mandatory front door for all img2threejs work on this
machine. Do not let a quality-gated workflow become an unbounded workflow.
Successful validation, a high automatic score, a running WebGL page, or a
rendered MP4 does not prove visual likeness.

## Mandatory start

Before img2threejs-specific planning, worker delegation, installation, code
generation, browser control, file mutation, validation, or export:

1. Read `references/img2threejs-production-handbook.md` completely.
2. Read the complete `SKILL.md` from the exact installed or candidate
   img2threejs version that will be used. For installation or update work,
   audit the candidate in a read-only checkout before mutation. Verify its
   path, version, tag, and commit when provenance matters.
3. Select exactly one primary route:
   `DIAGNOSTIC_ONLY`, `TOOLCHAIN_MAINTENANCE`,
   `RAPID_VISUAL_PROTOTYPE`, `REFERENCE_MATCHED_TURNTABLE`, or
   `ACTION_READY_PROCEDURAL_ASSET`.
4. Record the route contract before consequential work: target artifact,
   visible fidelity target, source authority, time budget, maximum visual
   cycles, evidence budget, designated visual approver, video lock, and
   escalation route.
5. Apply the lowest route that can satisfy the user's actual deliverable.
   Scope may be upgraded only through an explicit route review; never silently.

If the handbook or the selected installed or candidate Skill cannot be read,
stop before controlling img2threejs and report the missing authority.

## Route boundary

- `DIAGNOSTIC_ONLY`: inspect references, source, runtime, logs, or a failed
  model without mutation.
- `TOOLCHAIN_MAINTENANCE`: install, update, remove, pin, health-check, or
  verify the img2threejs toolchain. Do not start a production reconstruction
  unless the request includes one.
- `RAPID_VISUAL_PROTOTYPE`: produce a time-boxed, browser-orbitable visual
  approximation. It is not a formal full-pipeline or production-asset claim.
- `REFERENCE_MATCHED_TURNTABLE`: match the visible product well enough for
  approved representative stills and a turntable video. Build only the
  structure and motion required by that deliverable.
- `ACTION_READY_PROCEDURAL_ASSET`: run the installed img2threejs staged
  pipeline for an animation-ready or interactive asset with justified
  hierarchy, sockets, colliders, attachments, states, and full gates.

When a task combines routes, apply the highest downstream acceptance burden
only to the deliverables that actually need it. A requested turntable does not
inherit destruction, gameplay, or complete action-rig requirements.

## Non-negotiable operating rules

- Establish a recognizable fixed-view blockout early. Do not complete a large
  spec, PBR study, interaction rig, evidence archive, or video before the
  identity-bearing silhouette and component relationships are visually
  credible.
- Treat human or designated visual-approver rejection as final for that
  checkpoint. Automatic IoU, colour, coverage, schema, build, or runtime PASS
  may block promotion; it may never reverse a visible FAIL.
- Keep video locked until the route's representative stills pass. Motion,
  depth of field, or selective angles must not hide a failed model.
- Tune high-leverage geometry, camera, lighting, and material parameters with
  hot reload or temporary live controls. Run full validation only on a stable
  checkpoint, not after every numeric change.
- Change one explainable defect cluster per correction cycle. If the same
  identity defect survives two cycles, stop parameter-only tuning and perform
  a route or method review before a third cycle.
- Route transparent thick walls, refractive products, liquids, creams, hair,
  cloth, exact hidden structure, and uncalibrated multi-view demands through
  the method-fit gate. Switch to Blender, projection, photogrammetry, or a
  hybrid route when procedural Three.js cannot meet the declared target.
- Use one source writer and at most one independent visual checker. Additional
  agents are read-only evidence lanes. Do not let multiple workers mutate the
  same model or spec.
- Preserve rejected baselines as read-only, versioned evidence. Never overwrite
  a failed version to make the next version appear to have passed.
- Keep temporary workers project-scoped, visible, unpinned, checkpointed, and
  under the supervising task's route and budget. Do not interrupt an active
  worker with repeated micro-prompts when a checkpoint message will suffice.

## Honest completion

Keep these claims separate:

- toolchain healthy;
- source/spec/build valid;
- browser interaction working;
- visual candidate;
- designated visual approver accepted;
- video technically valid;
- action-ready asset approved.

Never collapse a rapid prototype into a reference-matched asset, a visual
candidate into an approved likeness, or a valid MP4 into an approved video.
Report the selected route, elapsed budget, completed and failed gates,
authoritative artifact paths, known approximations, and next owner.
